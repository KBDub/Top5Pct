## Section 1: File Migration Rules (carried forward from R3)

| # | Rule |
|---|---|
| 1 | Never remove any image file. Only move or copy. Even outdated or duplicate files stay on disk. |
| 2 | Apply `top5pct-` prefix to every incoming R4 filename on move. Spaces become hyphens. |
| 3 | Image dir name = last URL segment only. The dir does not mirror the full URL path. Example: `/custom-apparel/specialty-materials/glitter-shirts` goes to `glitter-shirts/`, not `custom-apparel/glitter-shirts/`. |
| 4 | Image paths are always flat under `public/images/<dir>/`. No sub-dirs within a category dir. |
| 5 | Source files must be moved, not copied. After verifying the moved file is in the target dir, the staging source is no longer needed, but per Rule 1 it stays on disk until a deliberate cleanup pass is approved. |
| 6 | No file is ever overwritten silently. If a target filename already exists, flag it and rename the incoming file to `top5pct-<name>-r4.jpg` before proceeding. |
| 7 | Track before and after image counts for every `public/images/<dir>` touched during migration. Record counts before any moves begin and update after each phase completes. |

## Section 3: Page Slot Structure

Every category page follows this standard layout. Slots are listed in visual order, top to bottom.

| Slot | Component | Name | Notes |
|---|---|---|---|
| 1 | `x-sections.hero-banner` (or equivalent) | **Banner** | Always first. Always uses one image from this page's category. |
| 2-5 | `x-ui.carousel-rotating-images` | **Carousel** | Targets 4 images, all from this page's category. May hold more only if all other non-cross-sell slots on the page are already filled with R1-R3 images. |
| 6+ | `x-sections.card-image-with-text` | **Content cards** | One image per card. Use same-category R1-R3 images. Alternate imagePosition left and right. |
| A | `x-sections.card-detailed-info` | **Detailed info** | May use one or two images (image1, image2). Same-category R1-R3 preferred. |
| L | `x-ui.card-banner-slide-in direction="left"` | **Slide-L** | May be a cross-sell or same-category. If cross-sell, image must be R1-R4. |
| R | `x-ui.card-banner-slide-in direction="right"` | **Slide-R** | Always a cross-sell to a different category. Image must be R1-R4. |

## Section 4: Placement Priority Rules

These rules govern which images go where, and in what order to fill slots.

### 4a — Banner (Slot 1)

- Always uses one image from this page's own category.
- Must be R1-R4. If only an Initial-round image is available, leave it and flag for a future round.
- Never use a cross-sell image in the banner slot.

### 4b — Carousel (Slots 2-5)

- Target: exactly 4 images, all from this page's own category.
- All 4 must be R1-R4. Replace any Initial-round or misplaced images with proper same-category R1-R4 images.
- If fewer than 4 same-category R1-R4 images exist: fill what you can, leave remaining slots empty or flagged — do not pad with off-category or Initial images.
- Carousel may expand beyond 4 only after every content card, slide-L, and slide-R slot on the page already holds a proper R1-R4 image.

### 4c — Content cards (Slots 6+)

- Fill with same-category R1-R3 images in round order (R1 first, then R2, then R3).
- R4 images are used here after the R1-R3 audit is complete.
- If not enough R1-R3 images exist to fill all cards, leave the remaining cards with their current images and flag them — do not remove or replace with Initial-round images.

### 4d — Slide-R (always a cross-sell)

- Must show an image from a different category.
- The cross-sell image must be R1-R4. Never use an Initial-round image in a slide-R.
- The linked category should be related (a complementary product type).

### 4e — Slide-L (may be a cross-sell)

- Can show a same-category or cross-sell image.
- If cross-sell, same rules apply as slide-R: image must be R1-R4.
- Prefer same-category R1-R3 image here before using a cross-sell.

### 4f — General cross-sell rule

- All cross-sell images (in any slide-L or slide-R) must reference files that physically exist in `public/images/<category>/` and carry R1-R4 status.
- Never reference a cross-sell image that lives in `custom-shirts/` or any generic catch-all dir.

## Section 5: R1-R3 Audit Format

When auditing a page, record its placement status in this format before suggesting any changes.

```
### <page name>
**File:** resources/views/pages/...blade.php

| Slot | Component | Current image | Dir | Round | Status |
|---|---|---|---|---|---|
| Banner | hero-banner | top5pct-....jpg | category/ | R1 | OK |
| Carousel 1 | carousel | top5pct-....jpg | category/ | Initial | Replace |
| Carousel 2 | carousel | top5pct-....jpg | category/ | R2 | OK |
...

**R1-R3 filled:** N of M slots
**Remaining to fill:** M - N slots
**Suggestions:**
- Carousel 1: replace with top5pct-....jpg (R1, same category)
- Slide-R: current image is Initial-round — replace with top5pct-....jpg (R2, cross-sell category)
```

**Status key:**

| Value | Meaning |
|---|---|
| OK | Slot holds an R1-R4 image from the correct category |
| Replace | Slot holds an Initial-round image or wrong-category image — a better option exists now |
| Flag | Slot holds an Initial-round image and no R1-R3 replacement exists yet — leave for future round |
| Wrong cat | Image is from the wrong category dir — fix regardless of round |
| Cross-sell OK | Slide-L or Slide-R with a valid R1-R4 cross-sell image |
| Cross-sell fix | Slide-L or Slide-R using Initial-round or wrong-category cross-sell image |

## Section 6: Scope of Current Work

We are working in two distinct phases. Do not mix them.

**Phase A — R1-R3 audit (current phase):**
- Fix carousel images so each carousel holds 4 same-category R1-R3 images.
- Fix any slot using an Initial-round image where a same-category R1-R3 image exists.
- Fix any slot using a wrong-category image regardless of round.
- Fix any slide-R or slide-L using a non-R1-R4 cross-sell image.
- Do not add R4 images yet.
- Do not change any text, layout, or component structure. Images only.

**Phase B — R4 placement (after Phase A is complete):**
- Extract and inventory `public/Top5Pct.Images.R4.zip`.
- Assign R4 files to target dirs per the file migration rules.
- Fill remaining open slots with R4 images following the same priority rules.
- Update this doc with R4 inventory and move log.
